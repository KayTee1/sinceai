# Next task

Use after finishing a task, after a merge, or at the start of a new session.
Don't start building.

1. Check `git status`, branch and recent commits. Read PLAN, HANDOFF and open
   REVIEW findings.
2. Update task states to match reality (merged = done).
3. Check time left against the timeline in PLAN. If behind, propose which
   "nice" features to cut.
4. Suggest the next task for each developer: highest-priority work on the
   demo path whose dependencies are done, with no overlapping files.
5. Replace HANDOFF with a short note: where we are, what's next, blockers.

Report the two suggested tasks and any cuts. Wait for the humans to confirm.
